1. **Blocker — PR 1 mixes incompatible version numbers and can prevent the migration indefinitely.** Where: spec.md:49, §§5.1–5.4 and §6.4; code/elastic.ts:39. Today Elasticsearch assigns internal, per-document versions. PR 1 introduces an unrelated Postgres sequence, fills Postgres only, and marks the existing Elasticsearch index current. Verification requires identical ID/version sets, but reconciliation replaces only missing or *older* Elasticsearch documents. For example, an existing document at Elasticsearch version 20 assigned Postgres version 1 remains mismatched indefinitely without further writes. Ordinary startup reprojections increment Elasticsearch versions even when content is unchanged. Consequently, `pgVerified` never latches and the proposal cannot perform its main job: turning Elasticsearch off. Subsequent external writes below version 20 also receive HTTP 409. The existing transient classification (src/ingest/transient.ts:23) treats these as nontransient, and ingestion skips after three failures (src/ingest/ingester.ts:206), potentially leaving the serving index stale. Elasticsearch documents these version rules (docs-index_, 8.19). Confirm: seed an existing document at internal version 20; assign it Postgres version 1 during first fill; repeatedly run the specified reconciliation and comparison. Then submit an update whose three attempted versions remain below 20. The migration needs an explicit transition into a common version namespace.
